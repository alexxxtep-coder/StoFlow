# STO.Flow 6.0 — Workshop Operations SaaS

STO.Flow 6.0 — новая рабочая SaaS-сборка, созданная на основе HTML-прототипов 5.1, 5.4, 5.5, 5.6 и 5.7 и инженерной основы STO.Flow SaaS 0.1.0. Эталон дизайна и основных сценариев — HTML 5.7. Данные приложения хранятся в Supabase, а не в `localStorage`.

> **Статус релиза:** функциональный расширенный MVP / пилотная сборка. Не объявляется production-ready: интеграции, публичная онлайн-запись, AI-провайдер, полные WIP-правила, зарплата, складские движения, юридические документы и live security review ещё требуют реализации.

## Реализованные рабочие зоны

- **Сегодня:** рабочие показатели, быстрый приём обращения, последние лиды и активные заказ-наряды.
- **Работа:** очередь обращений, преобразование обращения в заказ, список активных заказов и переход в карточку.
- **Заказ-наряд:** клиент и автомобиль, жалоба, строки работ/деталей, цены, задачи, история статусов, оценка суммы и учёт распределённых оплат.
- **CRM:** клиенты, несколько автомобилей на одного клиента, добавление карточек и просмотр базы.
- **Календарь:** внутренние записи, назначение ресурса/поста, блокировка пересечений в PostgreSQL.
- **Задачи и WIP:** отдельные задачи, связь с заказом, приоритет и статусы.
- **Parts.Finder:** заявка из заказа, ручные предложения поставщиков, создание закупки. Никакие внешние каталоги не имитируются.
- **Финансы:** регистрация поступлений, необязательное распределение платежа на заказ, учёт расходов.
- **Аналитика:** сводка по фактическим строкам заказов, платежам и расходам с явными ограничениями выборки.
- **Управление:** участники, роли для просмотра, каталог услуг, нормативы и ресурсы.
- **Помощник:** rule-based сигналы из реальных данных, не генеративный AI.
- **Автоматизация / интеграции / онлайн-запись:** статус текущих системных правил и честная индикация неподключённых внешних механизмов.

## Стек

- Next.js 15 App Router + React 19 + TypeScript
- Supabase Auth + PostgreSQL + Row Level Security
- Server Actions + Zod
- Tenant isolation через `tenant_id`, серверный membership-контекст и RLS

## Запуск на Windows

Требуется установленный стабильный Node.js LTS версии 20 или новее. Не рекомендуется использовать Alpha/Current-экспериментальную сборку Node.js.

1. Распакуйте `STO.Flow_SaaS_6.0` на диск с достаточным свободным местом, например `D:\Projects\STO.Flow_SaaS_6.0`.
2. В корне проекта создайте `.env.local` на основе `.env.example`:

```ini
NEXT_PUBLIC_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=sb_publishable_YOUR_KEY
NEXT_PUBLIC_APP_URL=http://localhost:3000
```

`NEXT_PUBLIC_SUPABASE_ANON_KEY` — историческое имя переменной; в ней можно использовать Supabase Publishable Key (`sb_publishable_...`). Secret / Service Role Key в `NEXT_PUBLIC_*` не добавлять.

3. В PowerShell перейдите в корень проекта (там должен находиться `package.json`).
4. Установите зависимости с npm-кэшем на диске проекта, чтобы меньше занимать диск C:

```powershell
npm.cmd install --cache .npm-cache --no-audit
```

5. Примените SQL в Supabase SQL Editor:
   - **Новая пустая база:** один раз вставьте целиком `supabase/STO.Flow_6.0_NEW_DATABASE.sql`.
   - **Существующая база, где уже применена 0001:** вставьте целиком `supabase/STO.Flow_6.0_EXISTING_DATABASE_UPGRADE.sql`. Не запускайте 0001 повторно.
   - Отдельные версионируемые миграции также лежат в `supabase/migrations/`.
   - Миграция 0002 пересоздаёт RPC `create_lead_with_context` с согласованным порядком именованных аргументов; миграция 0003 защищает финансовую целостность заказов и платежей; миграция 0004 блокирует закупку неподходящих, отсутствующих на складе или неоценённых предложений.
6. Запустите:

```powershell
npm.cmd run dev
```

7. Откройте `http://localhost:3000`.

PowerShell может блокировать `npm.ps1`; команды `npm.cmd` обходят это ограничение без изменения Execution Policy. Не закрывайте окно терминала во время работы сервера.

## Проверки

```powershell
npm.cmd test
npm.cmd run typecheck
npm.cmd run lint
npm.cmd run build
```

`npm test` запускает доменные тесты, включая нормализацию номера телефона и денежные инварианты. Build, интеграционные тесты, миграции и RLS должны быть выполнены в окружении с установленными зависимостями и подключённым тестовым Supabase.

## Важные ограничения и безопасность

- Публичный клиентский портал онлайн-записи ещё не открыт: для него требуются антиспам, rate limiting, согласия и безопасный публичный RPC.
- Реальные API поставщиков, VIN-каталоги, мессенджеры, телефония, платёжные шлюзы и AI-провайдеры не подключены.
- Приглашение сотрудников выполняется через Supabase Auth Dashboard; приложение показывает состав membership, но полноценный invite/role-admin workflow требует отдельной итерации.
- WIP сейчас представлен задачами/очередью; лимиты по этапам и автоматическое балансирование загрузки постов ещё не реализованы.
- На финансовом экране платежи и расходы не являются автоматически рассчитанной чистой прибылью. Не все суммы отражают бухгалтерский учёт.
- После обновления необходимо применить миграции 0002, 0003 и 0004 по порядку. 0002 содержит транзакционные RPC; 0003 защищает финансовую целостность; 0004 проверяет цену, валюту, применимость, наличие и состояние заявки перед закупкой.
- Для загруженного проекта Supabase отдельно выполнена read-only сверка схемы и политик; миграция 0004 подготовлена локально и ещё не применялась к базе. Перед коммерческим запуском обязателен независимый security review и тест доступа между двумя разными tenant.

## Папки проекта

- `src/app` — маршруты, страницы и серверные действия.
- `src/components` — общий интерфейс приложения.
- `src/domain` — доменные функции и unit-тесты.
- `supabase/migrations` — версионируемые SQL-изменения.
- `docs` — спецификация, аудит, статус готовности и модель безопасности.
- `references/html` — исходные HTML-прототипы для сверки UX.
