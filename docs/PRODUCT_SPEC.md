# Продуктовая спецификация — STO.Flow SaaS

## Позиционирование
STO.Flow — операционная платформа автосервиса, объединяющая обращения, расписание, заказ-наряды, выполнение работ, снабжение, коммуникации и управленческие финансы. Parts.Finder — модуль снабжения внутри той же платформы.

## Первый рынок
Независимые небольшие и средние СТО Беларуси, ориентир 2–10 рабочих постов. Язык интерфейса — русский; валюта BYN и timezone Europe/Minsk по умолчанию, но настраиваемые.

## Основной поток
Обращение → клиент/автомобиль → запись → заказ-наряд → работы и детали → поиск/сравнение предложения → закупка/приёмка → ремонт/контроль качества → выдача → платежи → аналитика/повторный контакт.

## Рабочие зоны
1. Сегодня — личные задачи, ближайшие записи, проблемные заказы и важные события.
2. Работа — входящие/коммуникации, запись, заказы, задачи.
3. Клиенты — люди/компании, автомобили, история и согласия.
4. Снабжение — Parts.Finder, заявки, предложения, поставщики, закупки, поступления.
5. Финансы — оплаты, долги, расходы, экономика заказов и начисления.
6. Управление — сотрудники, роли, ресурсы, услуги, статусы, интеграции и настройки.

## Роли
Owner, Admin, Service Manager, Service Advisor, Mechanic, Parts Manager, Finance. Роль не заменяет атомарные permissions; сервер и БД проверяют доступ.

## Основные инварианты
- Клиент может иметь несколько автомобилей.
- Заказ может иметь несколько строк работ и деталей.
- VIN необязателен; источник и уверенность идентификации фиксируются.
- Задача — действие, не копия заказа.
- Статусы имеют допустимые переходы и историю.
- Платёж и его распределение — источник факта поступления.
- Выручка, поступления, расходы, долг и валовая маржа — разные показатели.
- Предложение детали хранит источник и время актуальности.
- API поставщика не подключён, пока не проверен реальный доступ.
- ИИ формирует черновики; критические действия подтверждает человек.

## MVP-срез
Первый работающий сценарий: пользователь входит → работает в tenant → создаёт обращение → система атомарно создаёт клиента, при наличии параметров автомобиль, и обращение → запись появляется в списке обращений. Следующие срезы: заказ-наряд и запись, затем ручной Parts.Finder, затем финансы.
