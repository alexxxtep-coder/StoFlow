# План тестирования STO.Flow 6.0

## Автоматизировано в текущем архиве

Запуск: `npm test`.

- Граф допустимых и недопустимых переходов статусов заказ-наряда; сравнение с DB transition graph.
- Расчёт финансов в целых копейках; частичная/полная оплата; отказ при отсутствии цены.
- Защита от отрицательных/небезопасных сумм и точность десятичных значений.
- Нормализация телефона.
- Преобразование `datetime-local` с учётом timezone организации; форматирование; отклонение некорректных дат/timezone.
- Статические контракты SQL миграций: RPC signatures, роли, row locks, payment allocation, terminal-order guards, create-workspace guard и fixed `search_path`.

Текущий результат: **24/24 теста проходят**.

## Обязательные staging / live тесты

1. Tenant A не читает/не меняет tenant B; повторить для каждой таблицы и RPC.
2. Роли owner/admin/service_manager/service_advisor/mechanic/parts_manager/finance: сверить SELECT/INSERT/UPDATE/DELETE с матрицей прав.
3. `create_workspace`: повторный и параллельный вызов одного пользователя создаёт не более одного активного tenant.
4. `create_lead_with_context`: атомарность, дедупликация телефона, VIN/госномер, откат при ошибке.
5. Записи: два параллельных бронирования одного ресурса с пересечением — успешно не более одного; разные ресурсы/непересекающиеся интервалы — разрешены.
6. Время: Europe/Minsk, UTC, Europe/Amsterdam, timezone с DST; проверить отображение, запись и переход DST.
7. Заказ: полный граф переходов; запрет закрытых переходов; история и `completed_at`.
8. Завершённый/отменённый заказ: нельзя добавить строку, финансовую цену, задачу или заявку на деталь; прямой запрос к таблице тоже отклоняется.
9. Финансы: частичная/полная оплата, превышение остатка, чужой customer/order, другая валюта, missing price, конкурентные платежи; изменение цены/количества после оплаты не уменьшает итог ниже распределённых оплат.
10. Parts.Finder: ручное предложение с источником/временем, idempotent purchase, запрет закупки отклонённого/stale предложения; отдельная приёмка/остатки пока не реализованы.
11. Playwright: вход → обращение → клиент/авто → запись → заказ → строка → заявка детали → предложение → закупка → задача → оплата → архив/финансы.
12. Backup/restore на отдельной среде; нагрузка и мониторинг.

## Ограничения среды

Без доступного Supabase/PostgreSQL и установленных npm dependencies тесты 1–12 не могут считаться пройденными. Статические проверки SQL не заменяют выполнение миграций.
