## Найденные проблемы и локальные исправления в этой сборке

### 1. Небезопасное создание закупки

До исправления `create_purchase_from_offer` запрещала только предложения со статусом `rejected` или `stale`. Можно было создать закупку, даже если:
- применимость была помечена `not_fit`;
- наличие было `out_of_stock`;
- закупочная цена отсутствовала;
- заявка уже была `received` или `cancelled`.

Это было не только ограничение интерфейса: ту же операцию можно было вызвать напрямую через Supabase RPC.

**Исправление:** добавлена миграция `0004_procurement_safety.sql`. Она проверяет роль, валюту, состояние заявки, применимость, наличие и обязательность цены на стороне PostgreSQL; повторный вызов возвращает уже созданную закупку. UI также скрывает действие для заведомо неподходящих предложений. Дополнительные триггеры защищают прямую вставку в таблицу `purchases`, синхронизируют статусы заявки/предложения и блокируют прямое изменение/удаление закупки до появления отдельного процесса приёмки. Ручное предложение без цены сохранить можно, но закупку до заполнения цены создать нельзя.

### 2. Неправильная дата расхода около полуночи

Поле даты расхода использовало `new Date().toISOString().slice(0, 10)`, то есть календарный день UTC, а не часового пояса организации. В первые часы местного дня это могло подставлять предыдущую дату.

**Исправление:** добавлена `dateOnlyInTimeZone()`; значение по умолчанию теперь формируется в timezone организации. Добавлен тест для `Europe/Minsk` и `Europe/Amsterdam`.

## Что остаётся незакрытым

1. Нет `package-lock.json`; зависимости заданы диапазонами `^`. Для воспроизводимого CI/release нужен lockfile и закреплённые версии.
2. Не выполнены `npm install`, `next build`, ESLint и полноценная TypeScript semantic check.
3. Не выполнены browser E2E и live тесты RLS для двух tenant и семи ролей.
4. Не выполнены тесты конкурентных платежей и бронирований на PostgreSQL.
5. Внутри продукта пока нет публичной онлайн-записи, реальных API поставщиков/VIN-каталогов, мессенджеров, телефонии, платёжных шлюзов, AI-провайдера, полноценного приёма закупки и складских движений.
6. Нет приглашения сотрудников и полноценного управления членствами/ролями в интерфейсе; нет переключателя между несколькими организациями.
7. Репозиторий GitHub, предоставленный ранее, содержит только `README.md` и `LICENSE`; исходный код был в ZIP-вложении. В этот репозиторий изменения не отправлялись.

## Статус

Это улучшенная сборка для staging/контролируемого пилота, **не подтверждённый production-ready релиз**. Миграция 0004 подготовлена в файлах архива, но не применялась к Supabase. Перед её применением нужна резервная копия и тест на staging/в отдельной тестовой базе.
